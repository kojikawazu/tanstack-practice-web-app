## 背景・目的

**TanStack シリーズ（Router / Query / Table / Virtual / Form）を、実用的なアプリを通して体系的に学習・検証する**ことが目的。

題材として「認証付きタスク管理アプリ」を採用する。CRUD・一覧表示・フォーム・ルーティング・認証ガードが自然に登場し、TanStack 5本柱すべてを「実際の出番がある形」で試せるため。

## ステークホルダー

| 役割 | 説明 |
|------|------|
| 学習者（=開発者本人） | 本プロジェクトの実装者・主たる利用者 |
| アプリ利用者（想定） | タスクを登録・管理するエンドユーザー |

## スコープ

- ユーザー認証（登録 / ログイン / ログアウト / セッション維持）
- タスクの CRUD（作成 / 一覧 / 詳細 / 編集 / 削除）
- タスク一覧の **ソート・フィルタ・列制御**（TanStack Table）
- 大量タスク（数千件）の **仮想スクロール**（TanStack Virtual）
- 型安全なルーティングと **認証ガード**（TanStack Router）
- **Zod スキーマを front/api で共有**したバリデーション

### スコープ外（将来拡張）

- チーム共有・タスクの担当者割り当て（マルチユーザー協調）
- 通知・リマインダー
- 本番デプロイ・スケーリング
- モバイルアプリ

## 制約・前提

- **フロントは React**（Vite + TypeScript の SPA）を前提とする。
- **DB は PostgreSQL を Docker コンテナ**で動かす。
- **モノレポ構成**（pnpm workspaces + Turborepo）で front / api / 共有パッケージを管理する。
- 学習目的のため、機能の網羅より TanStack 各ライブラリの「正しい使い方」を優先する。
- 技術スタックの詳細は [`09-architecture-specification.md`](./09-architecture-specification.md) を参照。

## 主要な決定事項

| 決定 | 理由 |
|------|------|
| 題材を「認証 + タスク管理」とする | TanStack 5本柱すべてに自然な出番ができるため |
| API は Hono | 軽量・型安全で Vite/TanStack と相性が良い |
| ORM は Drizzle | SQL に近い型安全・軽量なマイグレーション |
| 認証はセッション Cookie（HttpOnly） | localStorage の XSS リスクを避けた安全なデフォルト |
| シードで数千件のタスクを投入 | TanStack Virtual を本来の用途（大量行）で検証するため |
