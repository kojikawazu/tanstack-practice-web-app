## テスト戦略

| レイヤー | ツール | 対象 |
|----------|--------|------|
| ユニット（フロント） | Vitest | 純粋関数（`format.ts` の日付変換、`form.ts` のエラー整形） |
| 統合（API） | Vitest + `app.request()` | 認証・タスク CRUD の HTTP 振る舞い（DB 接続あり） |
| E2E | Playwright | 登録→ログイン→作成→一覧反映→仮想スクロール |

## テストケース

代表ケース（実装済み）。正常系 1 : 異常系 2 以上を意識。

| # | ケース | 分類 |
|---|--------|------|
| 1 | 登録 → /me → ログアウト | 正常系 |
| 2 | 登録済みユーザーでログイン | 正常系 |
| 3 | タスク CRUD（作成/取得/更新/削除） | 正常系 |
| 4 | 一覧のカーソルページング（重複なし） | 正常系 |
| 5 | バリデーションエラー → 400 + フィールド情報 | 準正常系 |
| 6 | 重複メール → 409 | 準正常系 |
| 7 | 誤ったパスワード → 401 | 異常系 |
| 8 | 未認証で保護リソース → 401 | 異常系 |
| 9 | 他ユーザーのタスク → 404（存在秘匿 / IDOR 対策） | 異常系 |

## カバレッジ目標

学習用途のため数値目標は設けない。重点: 認証・認可（所有者スコープ）、バリデーション、ページング境界。

## テストツール・実行方法

```bash
pnpm test                 # 全ワークスペースのユニット/統合（Vitest）
pnpm --filter api test    # API 統合（要: docker compose up + db:migrate）
pnpm --filter web test    # フロントユニット
pnpm --filter web test:e2e  # E2E（要: api 起動 + seed 済み。chromium: playwright install chromium）
```

CI 自動実行は未設定（将来課題、docs/11 参照）。

## 原則

- テストは仕様の証明。失敗したら実装を直す（テストを実装に合わせない）。
- 正常系 1 : 異常系（準正常系 + 異常系）2 以上を目安とする。
- ビジネスロジックをモックしない。モックは外部 I/O のみ（本プロジェクトは実 DB に対する統合テストを採用）。
- `toBeTruthy()` 等の曖昧なアサーションを避け、具体的な値・ステータスコードで検証する。
